Research lab

For game enthusiasts and programmers who want to understand prices, build models locally, and only ship results to this site — not train on the web server.

Architecture (planned)

Website shows live public prices + optional precomputed scores (CSV / JSON you export). Your machine runs training (scikit-learn, XGBoost, PyTorch, etc.).

  • Collect → public APIs + polite search scrapes (title, price, URL, rating only).
  • Store offline → SQLite / Parquet / CSV under a local data/ folder (not committed with secrets).
  • Train offline → notebooks or scripts on your Mac.
  • Publish artefacts → e.g. ml/predictions.json or a small table Django can read.

What we already collect (product-only)

Fields allowed in scrapes and APIs:

  • Product title, price, currency, product URL
  • Public aggregate rating (stars / feedback %) when on the card
  • Store name, kind (official / retail / used / third-party)

Not collected: seller personal identity, addresses, phones, emails, private messages.

Data sources

Public APIs (preferred)

  • Steam storesearch + appdetails (live UK prices, discounts)
  • CheapShark multi-store PC deals
  • PSN public Chihiro / tumbler search JSON
  • FX open.er-api.com (GBP normalisation)

Public search HTML (BeautifulSoup, best-effort)

  • UK physical: CeX, eBay, GAME, Argos, Currys, Amazon UK
  • Digital: Humble, Fanatical, Green Man Gaming, GOG, CDKeys (+ search links for Epic, Eneba, GG.deals, ITAD)

External datasets (for offline ML)

SourceUseNotes
Kaggle — Steam / game datasets Features: genre, tags, review score, owners bands Check each dataset licence before reuse
SteamSpy / Steam Charts (public pages) Popularity / concurrent players proxies Polite rate limits; not official sales figures
VGChartz / company reports Shipment estimates (noisy) Often incomplete; treat as labels with high uncertainty
Your PriceRecord export Time series of prices you tracked /export/tracked.json is a starting point
ITAD / GG.deals historical (if licensed) True price history Prefer official API / licence over scrape

When no public CSV of total sales exists, only use published aggregates or estimates from research pages — never invent sales numbers from private data.

Algorithms worth trying (offline)

GoalModels / methodsInputs
Will price drop in N days? Logistic regression, Random Forest, Gradient Boosting, simple LSTM on price series Discount %, days since launch, season (Steam sale calendar), historical lows
Fair price / expected low Quantile regression, historical percentile (5th/10th) Price history, genre, review score
Buy-now vs wait score Rules + calibrated classifier (what we sketch heuristically today) % under launch, official vs keyshop gap, trend slope
Cluster similar deals k-means / HDBSCAN on feature vectors Genre tags, price band, discount depth
Anomaly / bad keyshop outlier Isolation Forest, z-score vs official price Store kind, gap to Steam, rating

Start simple: historical percentile + sale calendar rules often beat a half-trained neural net.

Feature ideas (deals + understanding)

  • Personal lowest-ever badge from your own tracked history
  • Sale calendar overlay (Steam Summer / Winter / Autumn / Spring)
  • Price confidence: how many stores agree within £1
  • Edition matcher: avoid comparing Standard vs Gold vs DLC
  • Region risk flag for keyshops (EU vs WW keys)
  • Wait curve: chart of predicted drop probability over next 30/60/90 days
  • Bundle detector: when a bundle is cheaper than the single title
  • Physical vs digital spread for UK (CeX vs Steam)
  • Export training pack: one-click CSV of snapshots for Jupyter
  • Model card page: metrics, train date, feature list (transparency)

Suggested local workflow

  1. Track 20–50 games you care about; run python manage.py refresh_prices daily.
  2. Export /export/tracked.json → convert to pandas DataFrame.
  3. Join Kaggle metadata on steam_app_id.
  4. Label rows: “dropped 15%+ within 30 days?” using future prices.
  5. Train/validate offline; save metrics + predictions JSON.
  6. Optional later: Django management command to load predictions for display only.

Ethics & safety

  • Respect robots / rate limits; cache aggressively.
  • Keyshops are riskier — models should not hide that.
  • Predictions are not financial advice.
  • Do not scrape private profiles or non-public sales data.
